# Design workflow checks

Use this after a real design session or when the operator changes the requested
review format.

## Anchor → whole-page pattern

1. Pick one high-signal block, normally the hero.
2. Show two comparable visual directions on that same block.
3. Repeat the selected direction in full before locking it.
4. Compose the complete homepage in one page-order artifact.
5. Review hierarchy, rhythm, balance, mobile priorities, and transitions before
   accepting section-specific edits.

Do not turn the page into a chain of isolated approvals. A block can look right
alone while the page fails as a composition.

## Handoff gate

Before saying the design is ready to send:

- open the artifact in a browser;
- verify every referenced image loads;
- use a self-contained HTML/archive or a real shareable URL when file paths are
  local;
- give the operator the exact handoff action, not just a filesystem path.

## Communication gate

Client messages are drafts unless the operator explicitly says they were sent.
Do not describe a client decision as agreed, or work as delivered, when it is
only proposed. If the operator asks for a whole-page demo mid-flow, acknowledge
the switch, preserve locked decisions, and continue with the full composition.

## Evidence from Nicky's Brume & Root session

The operator chose a mood direction with a bare `A`, later requested a complete
homepage demo after being led through hero/section review, could not see the
rendered images, and asked how to send the result to the client. These are
workflow signals: confirm terse choices, treat whole-page requests as a mode
switch, and make preview/image validation and client handoff part of the design
deliverable.
