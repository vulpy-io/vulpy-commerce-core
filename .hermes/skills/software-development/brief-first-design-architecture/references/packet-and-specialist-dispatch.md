# Evidence packets and specialist dispatch

## Cost boundary

Fox/scouts collect facts. Premium specialists create or validate from a packet; they do not re-explore the repository or web.

For a dashboard/portal concept, packet facts include: current visible sections/actions, API data actually exposed, existing assets/tokens, required empty/loading/error states, forbidden invented features, and commercial copy constraints.

## Dispatch boundary

`delegate_task` is scout-only and follows cheap global delegation routing. Do not use it for designer or architect work. Launch named profile wrappers (`hermes-designer`, `hermes-architect`) after a profile smoke proves the intended provider/base URL/model.

## Revision loop

One concept per premium turn. Review the generated artifact yourself (screenshot after CSS animations settle); if it fails, send one bounded delta revision with exact defects. Never say a revision is in flight without immediately dispatching it.

## Product-copy guard

A visual concept must not invent commercial behavior. Preserve known actions/data; do not add card management, auto-top-up, or multi-key controls before the product/API supports them. For Vulpy billing, cache-hit requests are paid usage unless the operator explicitly changes policy.
